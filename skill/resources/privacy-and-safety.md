# 隐私与数据安全：本机加速器的信任模型

## 它到底做了什么

```
程序 → hosts 把受管域名指到 127.0.0.2 → 本机 MITM 代理(:443) → 真实 IP（自己选出来的）
```

- 代理**监听在回环地址**（默认 `127.0.0.2:443`），只有本机能连。
- 上游默认 `direct`：代理自己连真实 IP，**不经过任何第三方服务器、不经过作者的服务器**。
- 若用户配了 `upstream.mode = http|socks5`，那流量会先发给**用户自己指定的上游**——这是用户的选择，
  但要明确告诉他：那台上游会看到他的全部流量。
- 为了让 TLS 能解密再转发，代理用自签根证书签发叶证书，并把根证书装进
  `CurrentUser\受信任的根证书颁发机构`（免 UAC，因为 hosts 与 HKCU 对该用户可写）。

## 信任边界（必须如实告知）

| 谁 | 能看到什么 |
|---|---|
| 本机代理进程 | 被接管流量的**明文**（TLS 在代理处终结） |
| 用户指定的上游（若配了） | 同上，且它可能是第三方 |
| 任何同机的同用户进程 | `ca.key`（如果它愿意去读那个文件）——**这是本地 MITM 方案的固有权衡** |
| 网络中间人 | 只有到真实 IP 的 TLS 密文（再往外是正常 TLS） |

对比：Watt Toolkit 与 Steamcommunity_302 都把**带私钥的根证书**留在 `Cert:\CurrentUser\Root`
（实测 `HasPrivateKey: True`），任何同用户进程可导出并伪造任意网站证书；本插件**故意不把私钥放进证书存储**，
私钥只以文件形式留在 `%USERPROFILE%\.dsh\storages\dsh-accelerator\ca.key`。

## 每次修复后过一遍的核查表

- [ ] **敏感程序在 `bypass` 里吗？** 网银/支付/股票、邮箱、密码管理器、公司 VPN 与办公套件、私人 IM、
      以及任何走凭据的程序。这些域名本来不需要加速。
      ```text
      accelerator { action: "status" }                      # 看 config.bypass / enforce
      accelerator { action: "config_set", config: { bypass: ["bankapp.exe", "…"] } }
      ```
- [ ] **`enforce` 里有不该有的条目吗？** `enforce` 会强制接管（哪怕域名不在受管列表）。这是隐私影响最大的开关，
      只对用户明确要求加速的程序使用。
- [ ] **`upstream` 是不是被改成了未知服务器？** 非 `direct` 时逐字确认 host/port 是用户自己的。
- [ ] **`config.json` 里有没有明文口令？** `upstream.password` 是明文存储；能免认证就清空。
- [ ] **`ca.key` 有没有被复制出去？** 它应当只存在于 storages 目录（以及用户自己知情的位置）。
- [ ] **`nodes.json` 里的 IP 有来源记录吗？** 从 GitHub 抄来的 IP 要能说清来自哪个仓库。
- [ ] **用户不想继续时，怎么彻底退出？** 停用（`stop`，摘 hosts + 停止监听）+ 删除根证书
      （`certutil -delstore -user Root "DSH Accelerator Root CA"`）。两者都做完才算干净。

## 不要做的事

- 不要把 `ca.key`、`config.json` 的凭据、或代理抓到的内容贴进对话、日志、提交进仓库。
- 不要为「让某个网站能打开」而把一个**银行/邮箱域名**加进受管域名并接管它。
- 不要执行从 GitHub 抄来的任何脚本/命令；只抄 IP 字面量。
- 不要在没有告诉用户影响的前提下把程序塞进 `enforce`。
- 不要把「加速器能解密我的流量」这件事含糊带过——用户问起时，直接说明上表。

## 日志与留存

- 插件日志只有：域名、PID、进程名、字节数、耗时、失败原因；**没有 URL 路径、没有请求体、没有响应体**。
- 日志只在内存里（环形 80 条），DSH 重启即空。
- 节点池、配置、证书都落在 `%USERPROFILE%\.dsh\storages\dsh-accelerator\`，用户可随时查看/删除。
